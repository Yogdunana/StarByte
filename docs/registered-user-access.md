# 注册账号与会员身份

普通注册及 CAS 首次创建账号均赋予 `user`（User）。CAS 认证只证明身份，不代表通过入会审批；旧环境中的 CAS_DEFAULT_ROLE=member 也不会自动授予会员。

User 可以申请会员/干事、查看自己的申请进度和个人资料，以及阅读 CMS/公告中授权的内容。其他业务接口由后端统一限制，菜单同步隐藏。系统管理员和有协会职务/自定义角色的账号仍按对应权限检查。User 不能访问通用文件列表或下载接口；本次不开放通用文件权限。

迁移 000072 创建基础角色并给没有任何角色、也没有会员档案的历史注册账号补上 User。已有角色、会员档案和审批实例不降级、不删除。若某账号被旧 CAS 配置误授 member，先核对真实入会记录，再通过角色管理撤销误授身份；不按注册时间批量降级。

CMS 编辑页面可设置“指定角色可读”，选择多个角色或输入自定义角色编码。任一有效角色匹配即可阅读；游客和不匹配账号无法通过详情、目录、列表或搜索读取。既有“公开”“登录可读”“按权限码可读”继续有效；公开表示所有人均可读，登录可读也包含 User。公告继续使用原有按角色/部门/人员的受众配置。

个人中心对 null 角色/权限数组做兼容，API 正常返回数组，避免注册后页面崩溃。

CAS / 本地注册创建的账号默认只有 `user`。注册必须填写邮箱，系统通过 SMTP 发送激活链接（`/verify-email?token=`），激活前不能登录（错误码 2015）。存量未删除账号在迁移 000074 中按上次登录或创建时间记为已验证。SMTP 密码只从环境变量 / 运行时配置读取，不得写入仓库。

软删用户会删除 `user_identities` 与 `user_roles`，清空部门/职务，并把 `member_profiles` 标为离会、释放 `student_no`。学号与校园身份可被新账号复用；新账号只有 `user`，不会自动出现在人员档案或恢复会员角色。硬删时 `audit_logs.user_id`、`flow_instances.initiator_id` 置空，其它仍被引用的外键返回 409。身份唯一冲突返回 409，而不是 500。

CAS 注册只会把学号写到已有档案（若有），不会创建在册会员档案。会员身份只通过入会审批 `GrantRole` 授予。

升级需执行 000074（以及此前的 000072/000073）后重建前后端。若回滚 000074，未验证账号的 `email_verified_at` 列会删除，激活表也会删除。
