第一章 总则

第一条

本协会名称为"深圳北理莫斯科大学计算机协会"，简称"深北莫计协"或"计协"；英文名称：Shenzhen MSU-BIT University Computer Association，简称"SMBU-CA"或"SMBUCA"；俄文名称：Компьютерная ассоциация Университета МГУ-ППИ в Шэньчжэне，简称"КА МГУ-ППИ"。

第二条

社团简介：本协会是由深圳北理莫斯科大学在校学生自愿组成的学术科技类学生社团组织，归属工程系。协会以服务学校信息化建设、培养计算机技术人才为使命，常态化开展编程培训、技术讲座、项目实践、竞赛组织、课程开发等活动。

第三条

本协会类别为学术科技类，层次为院系级，归属工程系。

第四条

本协会的指导单位为深圳北理莫斯科大学学生工作部（校团委）和工程系，负责协会的思想引领、注册登记、年审考核、换届审批等管理工作。

第五条

本协会的合作单位为条件保障部信息化中心（以下简称"IT中心"）。双方基于平等协商、优势互补的原则开展协作，协作范围包括但不限于：校内信息化项目的技术支持、学生技术人才的培养与推荐、技术交流活动等。

第六条

本协会的宗旨是：服务学校信息化建设与数字化转型，搭建校内计算机技术交流与实践平台，培养具有工程实践能力的技术人才。

第七条

本协会的基本任务：

  1. 开展技术交流与培训活动，提升成员技术水平；
  2. 承接校内信息化相关项目，培养成员实践能力；
  3. 组织技术竞赛与学术交流，营造校园学术氛围；
  4. 为各类组织提供课程支持，开发系列实操课程；
  5. 发挥政治引领作用，培养德才兼备的技术人才。

第二章 成员

第一节 成员资格

第八条

本协会成员分为候补成员（T7）、正式成员（T6）和干事（T5）三个层级。候补成员为入会审核通过后未满一个月的成员；正式成员为候补期满后转正、不隶属任何部门的会员；干事为隶属各部门、参与日常运营的成员。

第九条

入会条件：

  1. 深圳北理莫斯科大学具有正式学籍的全日制在读本科生或与莫大联合培养的研究生；
  2. 拥护中国共产党领导，理想信念坚定；
  3. 对计算机技术有兴趣或有一定基础；
  4. 遵守本协会章程，愿意履行成员义务。
第十条

入会程序：

  1. 提交入会申请，填写申请表单（含姓名、学号、年级、专业、联系方式、技能特长、意向部门等信息）；
  2. 参加协会组织的招新活动或面试；
  3. 经部门负责人初审、中心主任复审，由常务委员会审批通过；
  4. 登记注册，成为候补成员（T7）；
  5. 入会满一个月后，经直属部长确认转正，转为正式干事（T5）或正式成员（T6）。
第十一条

每名学生最多加入2个学生社团。

第十二条

申请类型区分：申请时须选择"会员"或"干事"通道。选择"会员"者不隶属任何部门，意向部门字段为非必填；选择"干事"者意向部门为必填项。会员不参与日常部门运营，但可参与课程和活动。

第二节 成员权利

第十三条

正式成员（T6）及干事（T5）享有以下权利：

  1. 参加协会组织的各项活动；
  2. 对协会工作提出建议和批评；
  3. 选举权和被选举权；
  4. 优先参与协会项目实践；
  5. 获得协会提供的培训资源；
  6. 监督协会财务和管理工作；
  7. 自愿退出协会。
第十四条

候补成员（T7）享有以下权利：

  1. 参加协会组织的各项活动；
  2. 对协会工作提出建议；
  3. 获得协会提供的培训资源；
  4. 自愿退出协会。
第十五条

候补成员不享有选举权、被选举权和表决权。入会满一学期的正式成员方可参选协会干部。

第三节 成员义务

第十六条

成员应履行以下义务：

  1. 遵守协会章程和各项制度；
  2. 执行协会决议，完成协会交办的工作；
  3. 积极参加协会活动，维护协会声誉；
  4. 按规定缴纳会费（如收取）；
  5. 保守协会秘密，不得泄露协会内部信息。参与涉及保密协议项目的成员，须签署保密协议。

第四节 退出与除名

第十七条

成员退出：

  1. 成员可自愿退出，须提交书面申请；
  2. 毕业离校者自动失去成员资格；
  3. 退出后须结清相关事项，交回协会资产（如有），移交所持有的协会技术资产。
第十八条

成员除名：

  1. 连续一个学期不参加协会活动者，视为自动退会；
  2. 违反协会章程、损害协会声誉者，经常务委员会讨论决定，予以除名；
  3. 被学校处以纪律处分者，自动失去成员资格。

第三章 组织管理制度

第一节 组织架构

第十九条

本协会设社团主要负责人、中心负责人及职能部门，组织架构如下：

架构总览

社长（1名）→ 副社长（4名，可增至5-7名）→ 三大中心主任（由副社长兼任）→ 七大职能部门（每部1-3名负责人，可增至5-7名）+ 两大技术团队群（非部门编制，项目制运行）

第二十条

本协会设社团主要负责人、中心负责人及职能部门：

  1. 社团主要负责人：社长（会长）1名；副社长（副会长）4名（成员人数超过100人时可增至5-7名）。
  2. 中心负责人（与副社长同级）：技术研发中心主任1名、运营管理中心主任1名、对外合作中心主任1名。中心主任由副社长兼任或担任，确保职级对齐。
  3. 职能部门7个，各部门设负责人1-3名（部门人数超过20人时可酌情增至5-7名）。
第二十一条

七大职能部门及其核心职能如下：

第二节 技术团队

第二十三条

技术团队为协会下设的兼职技术团队，非部门编制，独立运行，成员以项目制参与工作，获得相应劳务报酬。

团队名称定位核心职能协作模式
内核开发团队群对内与IT中心协作，承接校内信息化项目，负责核心技术攻关项目制，按项目结算
业务交付团队群对外承接校外商业定制开发项目，负责项目交付项目制，按项目结算
第二十四条

技术团队实行双负责人制，设置间接负责人（管理归属）和直接负责人（队长）两个角色，共同覆盖团队管理的"行政监督"和"日常运营"两个维度。

维度管理归属（间接负责人）队长（直接负责人）
角色性质行政监督，间接管理日常运营，直接管理
默认/任命方式系统默认为项目开发部部长由部长及以上级别主动任命
继承机制自动升级链路：部长→中心主任→社长无自动继承，需重新任命
主要职责资源协调、跨部门对接、监督审批任务分配、进度推进、团队日常管理
第二十四条之一

管理归属（间接负责人）机制：

  1. 管理归属默认指向项目开发部部长，主要负责跨部门资源协调、团队审批事项签字（如任务交接审批、晋升审批中的签字节点）、监督团队整体运作，不参与日常任务分配；
  2. 当部长离职时，系统自动按升级链路查找当前有效的管理归属：部长→技术研发中心主任→社长，无需重新任命；
  3. 系统定期检测管理归属字段指向的人员状态，若状态为"离职"或"卸任"，自动按链路查找下一级在职人员并更新字段值，同时记录变更日志；
  4. 若链路全员离职，系统触发预警，通知常委会处理。
第二十四条之二

队长（直接负责人）机制：

  1. 队长由项目开发部部长及以上级别（中心主任、社长）主动任命，从团队成员中选拔，不限于部长级别；
  2. 队长主要负责团队日常任务分配与进度推进、组织团队会议与协作、向管理归属（间接负责人）汇报团队状态；
  3. 任命时系统记录任命人（部长/中心主任/社长）和任命时间，用于追溯任命来源和权限验证；
  4. 仅原任命人及以上级别方可更改队长人选；
  5. 队长离职时需重新任命，无自动继承机制。系统检测到队长状态变更后，通知管理归属（间接负责人），由间接负责人通知任命人重新任命。
核心区别

间接负责人 = 系统自动继承（部长不在中心主任上，中心主任不在社长上）；直接负责人 = 人为任命（队长离职后必须重新选拔，不会自动由上级顶上）。

第二十四条之三

技术团队其他运行机制：

  1. 团队成员以兼职身份参与，不占用部门编制；
  2. 团队承接技术项目，成员按贡献获得劳务报酬；
  3. 项目收益扣除成员劳务后的剩余部分纳入协会公共发展资金；
  4. 内核开发团队与IT中心建立常态化协作机制，优先承接校内信息化需求。

第三节 部门职能详解

第二十五条

创新创业部职能：

  1. 负责组织大学生创新创业训练计划（大创）等赛事；
  2. 开展项目孵化、创业辅导、商业计划书撰写培训；
  3. 对接校内外创新创业资源；
  4. 组织创新创业类讲座和交流活动。
第二十六条

项目开发部职能：

  1. 负责软件系统的设计、开发与维护；
  2. 制定代码规范，组织代码评审；
  3. 管理协会代码仓库与技术资产；
  4. 承接校内信息化项目的技术实现；
  5. 为技术团队提供技术支持。
第二十七条

课程研发部职能：

  1. 负责课程体系的规划与开发；
  2. 为各类组织提供课程支持，开发系列实操课程；
  3. 组织课程讲师的遴选与培训；
  4. 负责课程的教学实施与质量评估；
  5. 沉淀课程资源，建立课程库。
第二十八条

综合行政部职能：

  1. 负责成员招新、档案管理、信息统计；
  2. 组织换届选举、干部培训、考核评优；
  3. 管理协会文件、印章、资产；
  4. 协调各部门工作，组织内部会议；
  5. 对接指导单位的行政事务。
第二十九条

品牌传播部职能：

  1. 负责协会品牌形象建设与维护；
  2. 运营协会新媒体平台，制作宣传内容；
  3. 设计活动海报、宣传物料、文创产品；
  4. 记录协会活动，撰写新闻稿件；
  5. 对外发布协会动态，提升协会影响力。
第三十条

战略关系部职能：

  1. 负责对外合作关系的建立与维护；
  2. 拓展赞助资源，争取活动经费与物资支持；
  3. 对接腾讯云、Icon等厂商合作；
  4. 为业务交付团队拓展外部项目资源；
  5. 维护与其他高校技术社团的联系。
第三十一条

赛事运营部职能：

  1. 组织校内技术竞赛、编程比赛、黑客松等活动；
  2. 承办或协办校级以上技术赛事；
  3. 组织学术交流、技术沙龙、企业参访；
  4. 负责活动策划、执行、总结的全流程管理；
  5. 对接竞赛资源，为成员提供参赛支持。

第四节 常务委员会

第三十二条

常务委员会（以下简称"常委会"）是协会的决策执行机构，由社长、副社长、各部部长组成。

第三十三条

常委会职权：

  1. 制定和修改章程（提交会员大会确认）；
  2. 制定年度工作计划；
  3. 提名社长、副社长候选人；
  4. 任命部门负责人；
  5. 授权任命技术团队队长（直接负责人），管理归属（间接负责人）由系统自动设定；
  6. 管理协会财务与资产；
  7. 决定协会日常重大事项；
  8. 审议成员提案；
  9. 在会员大会闭会期间，行使会员大会授予的其他职权。
第三十四条

常委会会议：

  1. 常委会实行圆桌会议制度，由社长召集和主持；
  2. 重大事项须经常委会讨论决定；
  3. 常委会决议须经出席会议的三分之二以上成员同意方可通过。
第三十五条

社长职权：统筹协会全面工作、对外代表协会、召集和主持常委会会议、兼任功能型团支部书记。

第三十六条

副社长职权：协助社长工作，按分工分管相应领域，可兼任中心主任。设第一副社长为运营管理中心主任，在社长缺位期间负责召集常委会会议和日常事务协调。

第三十七条

社长缺位应急机制：社长因请假、出国交流、生病等暂时无法履职时，不设"代社长"角色。所有决策权移交常委会集体行使。第一副社长在社长缺位期间负责召集常委会会议和日常事务协调，但不拥有社长的单项审批权（如500元以下支出审批、任命权等），这些权限须经常委会集体决议行使。社长恢复履职后，系统自动恢复其全部权限。社长缺位期间由常委会做出的决策记录保留，不因社长恢复而变更。

第五节 会员大会

第三十八条

会员大会是协会的审议确认机构，行使以下职权：

  1. 审议和批准章程及章程修改；
  2. 审议和批准协会年度工作报告；
  3. 对常委会提名的社长、副社长候选人进行确认（同意或否决）；
  4. 审议和批准协会年度财务预决算；
  5. 应当由会员大会行使的其他职权。
第三十九条

会员大会须有三分之二以上成员出席方能召开。决议须经出席成员过半数通过。章程的修改须经出席成员三分之二以上同意。

第四十条

会员大会每学期至少召开一次。经常委会提议或五分之一以上成员提议，可临时召开会员大会。

第四十一条

成员提案：

  1. 成员可向常委会提交提案；
  2. 常委会应在收到提案后15个工作日内予以答复；
  3. 重大提案由常委会讨论决定是否提交会员大会审议。

第六节 技术顾问委员会

第四十二条

协会设技术顾问委员会，由指导教师、IT中心技术骨干、校外技术专家组成，为协会技术发展提供咨询建议。

第四十三条

技术顾问委员会职责：

  1. 为协会技术发展方向提供建议；
  2. 指导重大技术项目的方案评审；
  3. 为技术团队提供技术指导；
  4. 推荐技术资源和合作机会。

第七节 指导教师

第四十四条

协会设指导教师1-2名，由学生工作部（团委）和工程系协商确定。

第四十五条

指导教师职责：

  2. 审核活动内容的专业性与合规性；
  3. 参与协会重要会议及关键活动；
  4. 对协会发展方向、成员培养提出建议；
  5. 监督协会经费使用，防范活动安全风险。
第四十六条

指导教师在系统中的角色定位：指导教师拥有独立系统账号，但不属于T1-T7任何层级，不参与日常运营管理。其权限仅限于特定审批节点的会签：500-1000元支出审批（与社长会签）、换届选举校团委审批环节的代录。指导教师可在系统内直接完成签字，也可线下签字后由社长代为录入系统（系统记录"线下签字·社长代录"标记）。

第八节 功能型团支部

第四十七条

本协会应成立功能型团支部，名称规范为"XX年度共青团深圳北理莫斯科大学计算机协会支部委员会"。

第四十八条

功能型团支部设置：

第四十九条

功能型团支部职责：

功能型团支部与协会业务的关系：

第四章 决策与表决制度

第一节 角色层级与权限模型

第五十五条

协会采用RBAC（基于角色的访问控制）多角色叠加机制。一个用户可同时拥有多个角色标签，有效权限为所有角色权限的并集（OR逻辑）。这一设计直接映射章程中普遍存在的一人多职情况。

核心示例

某用户同时担任社长、团支部书记、纪监委委员、技顾委委员四个角色。其有效权限 = 社长权限 ∪ 团支部书记权限 ∪ 纪监委委员权限 ∪ 技顾委委员权限，而非仅取社长权限。

第五十六条

角色层级定义如下：

层级角色名称决策权重对应人员决策层
T1常委会—社长+副社长+各部长（集体）是
T2社长2协会最高负责人是
T3副社长/中心主任1三大中心负责人+副社长4名是
T4部门负责人0.5各部部长是
T5干事0.25各部门基层成员否
T6正式成员0不隶属部门的正式会员否
T7候补成员0候补期未满的新成员否
特殊指导教师0非层级，特定审批会签否
特殊课程访客0非会员，仅课程选课否
第五十七条

决策层定义：T4（部门负责人）及以上级别（T1-T4）均属于决策层，有权参与协会级决策。T5及以下不参与协会级决策。

第五十八条

权重用于加权投票制中的计票。社长权重为2，副社长/中心主任为1，部长为0.5，干事为0.25。权重为零的角色不参与加权投票。未投票者的权重不计入总权重。

第二节 三种决策模式

第五十九条

协会决策采用三种模式，由决策发起人根据事项性质选择：

模式计票方式通过条件出席率要求适用场景
签字制顺序流转，每人有否决权全部签字通过不适用面试审批、晋升审批、任务交接、支出审批
等权投票制一人一票赞成率 ≥ 2/3出席率 ≥ 2/3常规议案、章程修改、换届确认
加权投票制按角色权重计票赞成权重 ÷ 总权重 ≥ 2/3不要求出席率紧急决策、1000元以上支出审批
第六十条

等权投票制细则：

  1. 表决主体为常务委员会时，表决权为全体委员；表决主体为会员大会时，表决权为全体干事（不含普通会员）；
  2. 出席率 = 实际投票人数 ÷ 应出席人数，须 ≥ 2/3 方为有效表决；
  3. 赞成率 = 赞成票数 ÷ 实际投票人数，须 ≥ 2/3 方为通过；
  4. 弃权票计入出席人数（已投票），但不计入赞成也不计入反对；
  5. 出席率不足时，表决结果为"无效"。
第六十一条

加权投票制细则：

  1. 按角色权重计票，总权重 = 实际投票人的角色权重之和（含弃权票权重）；
  2. 赞成率 = 赞成权重 ÷ 总权重，须 ≥ 2/3 方为通过；
  3. 弃权票的权重计入总权重，但不计入赞成权重；
  4. 加权投票制不要求出席率，适用于紧急决策时缩小参与范围；
  5. 参与范围可设定为：全体有表决权成员、T3及以上、T2及以上。
第六十二条

签字制细则：

  1. 签字采用顺序流转：低层级先签 → 高层级后签；
  2. 每个签字环节设24小时超时，超时后自动升级至上一级；
  3. 超时升级后低层级仍可补签，但不阻塞流程；
  4. 签字人须在查看前序评语后做出判断；
  5. 评语内容不向被审批人公开，仅供审批链路人员查看。

第三节 投票记录

第六十三条

所有投票表决须留存完整记录，包括：议案标题、议案内容、表决主体、表决模式、参与范围、发起人、应出席人数、实际投票人数、赞成票数/权重、反对票数/权重、弃权票数/权重、出席率、赞成率、表决结果、投票截止时间、发起时间。每位投票人的投票选项、角色权重和时间戳须记入投票记录子表。

第六十四条

表决结果分为：通过、未通过、无效（出席率不足）、进行中。投票截止时间到达后系统自动计票并判定结果。

第五章 负责人产生程序

第一节 任职条件

第六十五条

本协会社长须为共青团员（含中共党员、中共预备党员），功能型团支部书记须为共青团员（含中共党员、中共预备党员）。

第六十六条

社团主要负责人任职条件：

  1. 本协会正式成员，入会满一学期；
  2. 拥护中国共产党领导，理想信念坚定，政治素养过硬，积极弘扬和践行社会主义核心价值观，道德品行端正，奉献意识突出；
  3. 具有较强的组织管理能力、沟通协调能力和与社团发展相关的业务能力，能够创造性地开展工作；
  4. 具有较好的群众基础和威信，热心社团工作，乐于为同学服务；
  5. 在校期间无违反校纪校规行为，未受过纪律处分；
  6. 应为深圳北理莫斯科大学具有正式学籍的全日制在读本科生或与莫大联合培养的研究生；
  7. 具有至少一学期及以上学生社团工作经历；
  8. 必须为共青团员（含中共党员、中共预备党员）。
第六十七条

部门负责人任职条件：

  1. 本协会正式成员，入会满一学期；
  2. 拥护中国共产党领导，理想信念坚定；
  3. 具有较强的业务能力和组织协调能力；
  4. 学习成绩良好，无违纪记录。
第六十八条

每名学生最多加入2个学生社团，不得同时担任两个社团的主要负责人。

第二节 产生程序

第六十九条

社团主要负责人任期为一学年，任期届满应进行换届。因特殊情况需提前或延期换届的，须经指导单位批准，延期最长不超过3个月。

第七十条

社团主要负责人产生程序：

  1. 提名：由现任常委会综合评估后，提名社长、副社长候选人；
  2. 审议：常委会对候选人进行审议，形成提名方案；
  3. 确认：召开会员大会，由会员大会对提名候选人进行确认（同意或否决）；
  4. 公示：确认通过后，在全校范围内公示，公示期不少于5个工作日；
  5. 任命：报校团委审批后正式任命。
第七十一条

会员大会否决的处理：

  1. 如会员大会否决提名候选人，常委会应重新提名；
  2. 重新提名后再次提交会员大会确认；
  3. 连续两次否决的，由常委会与指导单位协商处理。
第七十二条

部门负责人产生：

  1. 由竞聘选拔或常委会提名；
  2. 经常委会讨论决定；
  3. 任期与社团主要负责人同步。
第七十三条

晋升至部长及以上职务的申请，须经常委会终审；晋升至干事的申请仅需面试签字制，不涉及决策层审批。晋升审批流程：部门负责人初审 → 中心主任复审 → 常委会终审（如涉及决策层职务）。每级审批可选择通过或驳回，驳回需填写驳回理由。

第七十四条

技术团队双负责人产生：

  1. 管理归属（间接负责人）：系统默认为项目开发部部长，部长离职时按升级链路自动继承（部长→中心主任→社长），无需人工任命；
  2. 队长（直接负责人）：由项目开发部部长及以上级别（中心主任、社长）从团队成员中选拔任命，不限于部长级别，不占用部门编制；
  3. 任命时系统记录任命人和任命时间，仅任命人及以上级别可更改队长人选；
  4. 队长离职后需重新任命，无自动继承机制；
  5. 队长接受管理归属（间接负责人）的监督，并向其汇报团队状态。
第七十五条

工作交接：换届结束后7个工作日内完成工作交接，交接内容包括财务账目、档案资料、资产清单、活动计划、技术资产、项目进展等，交接双方须在交接清单上签字确认。

第六章 财务制度

第七十六条

协会经费来源：

  1. 学校拨款；
  2. 社会赞助（须报指导单位审批后接受）；
  3. 技术团队项目收益（扣除成员劳务后的剩余部分）；
  4. 会费收入（如收取，须经会员大会确认并报校团委审批）；
  5. 其他合法收入。
第七十七条

协会经费必须用于协会集体活动，任何单位和个人严禁侵占、私分或挪用。

第七十八条

预算管理：

  1. 每年年初编制年度经费预算，经常委会审议通过后报指导单位备案；
  2. 预算调整须经常委会批准，大幅调整（超过原预算20%）须报指导单位审批。
第七十九条

支出审批权限按金额分级：

金额范围审批角色审批方式
500元以下社长（T2）单人审批
500-1000元社长 + 指导教师双人会签
1000元以上常委会（T1）集体决策。默认等权投票制（出席率≥2/3 + 赞成率≥2/3）；社长可选择加权投票制（T3及以上参与），加权投票制不要求出席率
第八十条

技术团队收益分配：

  1. 项目收益优先保障参与成员劳务报酬；
  2. 成员劳务报酬根据项目贡献度协商确定；
  3. 扣除成员劳务后的剩余部分纳入协会公共发展资金；
  4. 收益分配方案须经常委会审议，报指导教师知晓。
第八十一条

财务公开：

  1. 每学期向全体成员公布一次经费使用情况；
  2. 在协会公众号或公告栏公示；
  3. 会员有权查阅协会财务账目。
第八十二条

财务监督：

  1. 常委会对财务工作进行内部监督；
  2. 接受全体成员的监督；
  3. 接受指导单位的审计和检查。

第七章 任务流转制度

第一节 任务生命周期

第八十三条

协会实行OA式任务流转管理，覆盖任务发起、审核、分配、执行、验收、归档全流程。

第八十四条

任务状态流转：

  1. 发起 → 待审核 → 审核通过/驳回 → 待分配 → 已分配 → 执行中；
  2. 执行中如需跨部门转交，进入待并签流程；
  3. 部门内任务直接提交验收；
  4. 并签通过/并签驳回 → 待验收 → 验收通过/驳回 → 已归档；
  5. 并签驳回退回原执行人。

第二节 权限规则

第八十五条

任务权限按层级分配：

  1. T5（干事）：可领取任务、更新进度、上传附件、添加评论；
  2. T4（部门负责人）：可分配任务、初审、参与协会级决策；
  3. T3（副社长/中心主任）：可跨部门调度、终审。

第三节 跨部门并签

第八十六条

并签适用场景：

  1. 跨部门转交任务：发起方部门负责人 + 接收方部门负责人并签确认；
  2. 跨中心转交任务：增加双方中心主任审核；
  3. 多部门协同任务：涉及的所有相关部门负责人会签确认。
第八十七条

部门内转交、任务交接（离职/繁忙场景）不适用并签，走直属上级审批流程。

第八十七条之一

技术团队任务分配特殊规则：

  1. 分配给技术团队的任务，默认发送给团队队长（直接负责人）而非部门部长；
  2. 队长可将任务进一步分配给团队成员；
  3. 技术团队的任务交接审批，由管理归属（间接负责人）签字确认；
  4. 当队长字段为空时，系统提示管理归属（间接负责人）尽快任命队长，在此期间任务暂存待分配状态。

第四节 超时自动升级

第八十八条

任务超时处理：

  1. 任务超过截止日期后，系统自动通知执行人的直属上级；
  2. 超时48小时再升级至更上一级；
  3. 升级链路：执行人 → 部门负责人 → 中心主任/副社长 → 社长 → 常委会（集体决策）；
  4. 防止任务搁置无人处理。
第八十九条

上级自动查找机制：系统通过人员档案表 → 部门表 → 层级关系自动解析直属上级，无需手动指定审批人。干事→所属部门负责人；部门负责人→所属中心主任；中心主任/副社长→社长；社长→常委会（集体决策）。

第九十条

签字超时规则适用于所有采用签字制的工作流：面试签字、晋升审批、任务交接、跨部门并签等。每个签字环节设24小时超时，超时后自动升级至上一级。超时升级后低层级仍可补签，但不阻塞流程。

第八章 对外协作与商业项目

第九十一条

与IT中心的协作：

  1. 协会与IT中心基于平等协商、优势互补的原则开展协作；
  2. 协作范围包括：校内信息化项目的技术支持、学生技术人才的培养与推荐、技术交流活动等；
  3. 内核开发团队优先承接IT中心委托的项目；
  4. 具体协作事项由双方根据实际需求协商确定，可签订书面协作协议；
  5. 协会承接IT中心项目，须经常委会审议并报指导教师知晓。
第九十二条

对外商业项目：

  1. 协会可通过战略关系部承接校外商业定制开发项目；
  2. 商业项目须由业务交付团队执行，部门成员可自愿参与；
  3. 承接商业项目须经常委会审议通过，报指导单位审批；
  4. 商业项目合同须经指导教师审核，重大合同须经指导单位审批；
  5. 商业项目收益分配按本章程第八十条规定执行。
第九十三条

对外合作与赞助：

  1. 协会与其他高校学生组织、企业、社会机构的合作，须经常委会审议通过；
  2. 接受社会赞助须报指导单位审批，任何个人不得私自接受赞助；
  3. 对外合作不得损害学校和协会声誉，不得从事违法违规活动。
第九十四条

课程开发与教学：

  1. 课程研发部负责为各类组织提供课程支持；
  2. 开发系列实操课程，涵盖AI工具应用、Office进阶、学业辅导、公文写作等方向；
  3. 课程开发须经常委会审议，报指导教师审核；
  4. 课程讲师可从技术团队中遴选，给予相应劳务报酬；
  5. 涉及保密内容的课程项目，参与成员须签署保密协议。

第九章 技术资产与知识产权

第九十五条

协会技术资产包括但不限于：代码仓库、技术文档、项目成果、培训资料、设计作品、课程资源等。

第九十六条

技术资产管理：

  1. 项目开发部负责代码仓库管理；
  2. 课程研发部负责课程资源管理；
  3. 品牌传播部负责设计作品管理；
  4. 建立技术资产清单，定期更新；
  5. 技术资产归协会所有，成员不得擅自对外披露。
第九十七条

知识产权归属：

  1. 协会成员在参与协会项目期间产生的技术成果，其知识产权归属由协会与相关方协商确定；
  2. 技术团队承接商业项目产生的知识产权，按合同约定处理；
  3. 协会自有项目的知识产权归协会所有。
第九十八条

技术资产移交：

  1. 成员退出协会时，须移交所持有的协会技术资产；
  2. 换届交接时，技术资产须完整移交，并更新资产清单；
  3. 项目结束时，项目资料须归档保存。

第十章 社团终止

第九十九条

协会有下列情形之一的，应当终止：

  1. 完成协会宗旨或自行解散的；
  2. 会员大会决议解散的；
  3. 被学校注销的；
  4. 由于其他原因终止的。
第一百条

协会终止的决议须经会员大会出席成员三分之二以上通过，报指导单位批准。

第一百零一条

协会终止前，须成立清算组进行清算。清算组由社团主要负责人、指导教师及相关人员组成。

第一百零二条

清算组职责：

  1. 清理协会债权债务；
  2. 处理协会剩余财产；
  3. 移交技术资产和档案资料；
  4. 办理协会注销手续。
第一百零三条

协会终止后的剩余财产，按照学校有关规定处理，任何单位和个人不得侵占或私分。协会终止后的档案资料和技术资产，按学校档案管理规定移交指导单位保存。

第十一章 章程修改程序

第一百零四条

章程修改的提议：

  1. 常委会认为必要时，可提出章程修改议案；
  2. 成员可向常委会提交章程修改提案；
  3. 指导单位认为必要时，可建议修改章程。
第一百零五条

章程修改的程序：

  1. 提出修改议案或提案，说明修改理由和内容；
  2. 常委会审议议案，形成修改草案；
  3. 功能型团支部对修改草案进行政治把关；
  4. 将修改草案提交会员大会确认；
  5. 会员大会须有三分之二以上成员出席，经出席成员三分之二以上同意方可通过；
  6. 修改后的章程报校团委批准后生效。
第一百零六条

章程修改后，应及时向全体成员公布，并报指导单位备案。
