# Application languages

StarByte supports `zh-CN`, `en-US`, and `ru-RU`. The login page, public navigation,
account settings, and authenticated header expose language selection. The choice is
saved in the browser; changing language preserves in-progress forms. Ant Design,
dayjs, browser title, dates, and number formatting follow the selected language.

## Adding application text

- Existing semantic keys remain in `frontend/src/locales/{language}.json` and use `t()`.
- Previously hardcoded text is in `{language}.text.json`, with its Chinese source as
  the key. Use `tx(source, values)` from `@/i18n/text`. Keys in this namespace are
  literal strings, including periods and colons. Do not interpolate strings before lookup.
- Components using `tx` subscribe with `useLocale()` (or their existing
  `useTranslation`). Include the current language when memoizing translated output.
  Module-level option labels use getters so they do not freeze at startup.
- Add all three translations together. `src/i18n/catalog.test.ts` checks matching
  keys, interpolation variables, and coverage of literal `tx` calls.
- Preserve user-authored content, names, business identifiers, URLs, and technical
  format identifiers. System workflow notification labels and default descriptions
  are translated when displayed; applicant data and custom text stay unchanged.

## API messages and generated files

API requests send `Accept-Language`. `backend/pkg/locale` selects supported languages
from the header and translates known application response messages, retaining error
codes and dynamic values. Unknown diagnostic text remains unchanged. Add backend
messages to both embedded English and Russian catalogs; Chinese source text is the
fallback. The locale package tests catalog parity and format tokens.

Export requests carry a server-selected, internal locale through synchronous and
asynchronous rendering. Built-in HTML/PDF templates, export labels, and PDF footers
follow it. User-supplied table values are not translated. The embedded Unicode font
supports Chinese and Cyrillic. SMTP test emails use the language of the test request.

No database migration or persisted user-language field is introduced. Existing
custom workflow templates, historical user messages, and administrator-authored
content are not automatically rewritten.

## Validation

Frontend: TypeScript, ESLint, all 123 tests, and production build. Regression tests
cover language changes with an open role form and system notification data.
Backend: race-enabled locale, response, export, configuration, and notification tests.
Russian/Chinese mixed PDF output was rendered and visually checked. The Russian
login page and language persistence were checked in the browser.
