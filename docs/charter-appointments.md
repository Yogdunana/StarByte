# 协会职务与章程审批（迁移 000073）

## 任命和兼任

技术管理员使用「系统管理 → 角色管理 → 角色成员」登记已决定的任命；此页面不代替选举或任命程序。

- `admin` 仅为技术管理账号。迁移移除其历史种子数据中的会长身份；其他人的既有身份不会因此删除。
- 会长 `president`：不绑定部门，仅允许一名有效在任会长；交接时先卸任再任命。
- 副会长 `vice_president`、中心主任 `center_director`：必须选择所负责的中心。
- 部长 `minister`：必须选择至少一个部门。
- 同一个人可分别拥有上述职务，每项任命独立记录范围，不覆盖个人主部门。编辑范围或移除任命后会使该用户权限缓存失效。
- 系统账号不自动拥有协会职务；任命接口由系统管理员操作，实际审批重新核验有效角色与范围。已停用部门的显式范围不回退为用户主部门。

兼任者可在不同环节分别签字；不能审批自己的入会申请。同一个常委会节点每人只生成一个任务。

## 新默认入会流程

对仍保持 000070 原始默认图的系统，迁移发布新版本：部门初审 → 中心复审 → 常委会会签 → 一个自然月候补期 → 直属部长确认转正。

- 干事申请在部门初审、中心复审前分别完成一面、二面。分数不自动决定录用。
- 普通会员申请无需选择加入部门，由综合行政部（部门代码 `admin`）及其所属中心负责审核。审批责任部门不等于该会员的组织归属。
- 常委会审批节点默认采用全体会签（全部有效待办须通过）；这是模板的签字策略，会议中的加权表决仍使用独立投票模块。成员由实际会长、副会长、中心主任、部长构成，技术管理员不在其中。
- 部门或中心缺少有效审批人时失败并提示，不能跳过必需节点。上级代签仍须等待 24 小时并填写原因。
- 候补身份 `probationary` 在到期前不授予正式 member/officer。到期后进入申请详情的正式审批面板，由直属部长签字确认；有未处理异议时不能转正。确认后按申请类型授予 member 或 officer。
- 新链增加超时及候补到期提醒，仍不自动批准。已有通知渠道由原调度器发送。

**已有自定义审批图和正在运行的实例保留。** 不会静默覆盖流程设计器发布过的修改。`docs/charter-admission-template.json` 提供新模板；对自定义系统，先核对现有节点后通过流程设计器发布适合本组织的新版本。已有旧申请继续按原版本完成，不会补造签字或追溯改写历史。

## 表决权重

新默认加权配置：会长 2；副会长/中心主任 1；部长/副部长 0.5；干事 0.25；普通会员、候补和纯技术管理身份 0。同一人在一次表决中只计一次，取其有效职务中的最高已配置权重，不相加。角色任命不依赖个人资料的单一 position 字段。

已经冻结的投票名单与权重不重算。只有仍等于原始种子配置的全局权重会被迁移更新；自定义权重需管理员在「会议 → 权重配置」核对。普通等额表决保留原有一人一票模式。

## 上线与回退

1. 先部署包含 000072 的注册权限修复，再应用 000073 和对应代码。
2. 核对管理员身份、实际任命、部门/中心范围及在用流程图；缺少负责人的流程不能正常发起。
3. 清理或等待旧权限缓存过期，重新登录核对菜单；随后用测试账号走完整入会链。
4. 000073 down 为兼容回退，保留新增字段、任命数据及审批历史，不恢复 admin 的错误会长身份。再次 up 可重复执行。旧代码不能正确处理新章程实例，已有新申请时不要单独回退应用代码。

验证包括：真实 PostgreSQL 中的完整审批和候补确认、兼任分别签字、非管理员不能任命、部门范围停用后拒绝回退、角色移除、最高权重去重、中文/英文/俄文资源、前端 lint/build。共享测试库中的旧测试会清空工作流表，因此 CI 串行执行测试包，避免包间互相破坏数据。
