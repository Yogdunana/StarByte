# 联测更新：审批通知与审计 IP

流程待办通知现在携带当前环节、业务上下文以及 `/workflow/todo?task_id=...` 链接。缺失或损坏的通知模板会使用明确的待办内容，不再仅显示“新通知”。已有历史泛化通知没有任务编号，无法可靠还原申请人；点击后打开待办清单，不能据此自动关联某份申请。目标任务与申请详情仍由后端校验访问权限，已处理任务可以查看记录。

生产 Compose 增加独立的 `web-proxy` 网络，前端 Nginx 固定为 `172.30.77.2`，后端只信任该地址提供的转发头。后端仍连接原有默认网络访问数据库、Redis 和对象存储。其他来源直连后端时，不信任其自报的客户端 IP。

更新后需用同一 Compose 项目重建前后端容器，使网络和 `TRUSTED_PROXIES` 生效。不要执行 `down -v`。如果 `172.30.77.0/29` 与现有网络冲突，请同时调整 `.env.example` 中的子网、前端地址、后端地址和信任列表。不要把信任范围设为全部地址。

若 Nginx 前还有学校网关、负载均衡或其他反向代理，需由部署方确认实际链路及它们是否正确追加/覆盖转发头，再配置准确的受信地址；应用无法从缺失的转发信息还原真实地址。

验收：通过页面执行一项可审计操作，日志地址应为客户端地址或上游实际提供的地址，而非前端容器地址；附带伪造 `X-Forwarded-For` 的直接请求不能改变记录的来源地址。此改动只影响之后产生的记录，不重写历史审计数据。
